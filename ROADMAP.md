# GuavaKt demand-led roadmap

## Goal

Build the best Kotlin-first, coroutine-native Guava-equivalent library for Kotlin Multiplatform. Every public Guava concept receives an explicit outcome:

- **Port** when Kotlin has no adequate equivalent and the semantics are portable.
- **Adapt** when the capability is valuable but Kotlin nullability, `Duration`, coroutines, `Flow`, or an established KMP library produces a better API.
- **Guide to stdlib** when Kotlin already solves the problem well.
- **Platform tier** when honest behavior requires GC, filesystem, blocking, reflection, or another runtime facility.
- **Exclude with rationale** only for Java binary linkage, Java serialization form, private implementation layout, or an intrinsically JVM-only mechanism with no useful KMP meaning.

Completeness means exhaustive disposition plus deep behavior tests. It does not mean copying Java implementation classes or preserving poor Java ergonomics.

## What developers ask for

These sources are directional evidence, not a statistically representative survey. Feature requests and real downstream migrations should supersede page views when the project is public.

## Implementation order

### P0 — adoption blockers

1. Finish deep Multimap/Multiset/BiMap/Table contracts: every live view, iterator mutation, ordering rule, equality rule, null rejection, and serialization-independent copy behavior.
2. Deepen the coroutine-native cache now that loading and stale refresh have explicit scope ownership, same-key stampede control, per-key concurrency, `Duration`, deterministic test clocks, invalidation-race protection, observable stats, and JMH traces for controlled hot-hit, same-key, distinct-key, and bounded-eviction workloads; next use profiler evidence and downstream workloads to guide tuning.
3. Continue the Okio migration now that injected `FileSystem` reads/writes, streaming-native byte and UTF-8 character sources/sinks, lazy slices/concatenation, parent creation, and traversal work in common code: test Native/Node system filesystems, extend character encoding tiers beyond portable UTF-8 only where useful, and document explicit browser limitations.
4. Continue coroutine adaptation now that rate limiting, future/service bridges, aggregate `ServiceManager` observation, and guarded `CoroutineMonitor` state are non-blocking common APIs with explicit cancellation ownership, multiplatform tests, Guava differential traces, and high-contention cancelled-rate-reservation coverage; next benchmark wake-up behavior and broaden cancellation/completion race seeds.
5. Publish usable artifacts, generated API docs, migration recipes, compatibility tables, and runnable samples.

### P1 — differentiated Guava capabilities

1. Keep long-running Range/RangeSet/RangeMap fuzzing focused on newly discovered cut interactions; comparator-equivalent endpoints, 16-seed × 256-operation integer traces, nested derived-view iterator behavior, and property-controlled 180-digit arbitrary-precision `BigInteger` domain traces are now directly covered.
2. Keep long-running Graph/ValueGraph/Network fuzzing aimed at newly discovered ordering interactions; eight-seed × 320-operation directed/undirected traces plus stable and sorted comparator-alias behavior are now directly covered.
3. Continue hashing performance and streaming work now that BloomFilter has Guava 33.6 bit-level/wire parity, atomic common writes and unions, Murmur3-128 vectors, standard/custom-funnel byte identity, FPP/cardinality queries, executed JVM/JS/Wasm/macOS Native contracts, JMH graph/hash/cache traces, and Okio streaming adapters; next add sustained performance baselines where they improve real use.
4. Network parsing, public-suffix freshness, escaping, and IP edge cases. Portable byte-array `InetAddresses` now matches the useful transition-address layer too: compatible, 6to4, Teredo, and ISATAP recognition/extraction; exact Guava IPv6 coercion; maximum/no-wrap successor and predecessor behavior; and little-endian conversion. The PSL now has a semantic audit plus compact-trie generator against its official source; its status deliberately reports a stale snapshot rather than hiding it. Remaining work is a reviewed data refresh, scoped-address policy, and explicitly excluded arbitrary-precision conversions.
5. Continue Math/primitives/statistics edge auditing: `IntMath` and `LongMath` rounded arithmetic boundaries (including base-10 logs and deterministic full-`Long` primality), `DoubleMath` every-mode ties/non-finite/range checks, Type-7 quantiles, paired regression, linear transformations, and arbitrary-precision common numeric operations are now direct-compared. `BigInteger` powers roots, rounded division, factorial/binomial, and logs beyond `Long`; `BigDecimal` preserves arbitrary scale and `BigDecimalMath` exactly compares decimal values to binary `Double` boundaries for every rounding mode. Deterministic 180-digit JDK/Guava fuzzing is routine; next prioritize additional decimal arithmetic operators and larger sustained fuzz runs.

### P2 — exhaustive public surface

1. Inventory every public class and top-level capability in the pinned Guava oracle version.
2. Record each as ported, adapted, stdlib-guided, platform-tiered, or excluded with rationale.
3. Add typed Guava differential tests for all behavior where a JVM oracle is meaningful.
4. Mine upstream Guava tests and fixed bugs for obscure contracts; add reduced KMP regression tests.
5. Repeat on each deliberate Guava oracle upgrade, with an API and behavior delta report.

Private Guava implementation classes such as `RegularImmutableList` are not product surface. Their observable contracts still matter and belong in tests of the public type.

## Current public-class baseline

`python3 scripts/guava_class_inventory.py` compares top-level public Guava source types with GuavaKt names. At the initial demand-led baseline, 313 of 332 public Guava names were represented. Okio sources/sinks, `AtomicLongMap`, array-backed escapers, mutable runtime-typed maps, deprecated `TreeTraverser`, forwarding decorators, and honest JVM-only blocking/reflection tiers brought the current name inventory to all 332 of 332. This number is deliberately **not** a behavioral completion percentage: represented names still need deeper contracts, overload dispositions, and upstream edge-case mining.

No public top-level Guava name is now absent from the inventory. JVM-only `AbstractInvocationHandler`, raw-type `Invokable`, and `TypeParameter` preserve meaningful Java reflection behavior without pretending that `java.lang.reflect.Type`, dynamic proxies, or free type variables are portable. Name inventory remains informational; behavioral evidence is still the governing metric.

The current deep-parity pass is working through the flagship collection contracts rather than adding more names. `Multimaps.filterKeys`, `filterValues`, and `filterEntries` now produce lazy live views with predicate-safe additions, removal write-through, nested-filter composition, nullable-key handling, set-preserving overloads, and list-preserving indexed key filters. `transformValues` and key-aware `transformEntries` are lazy views whose removal routes mutate the source while inverse mutations remain unsupported.

The same pass now covers the core collection contracts that hand-rolled Kotlin multimaps and multisets most often lose. Absent list reads no longer materialize keys; held Multimap entry views remain live and write through; nullable keys survive keys-multiset removal; and `LinkedListMultimap` entries and instances have Guava value semantics. Map-backed Multisets now share overflow-safe `Long` bookkeeping, saturate public size, preserve nullable elements, expose live element and count-entry views, remove exact-count entries correctly, and compare/hash/format by counts across mutable, immutable, sorted, and forwarding variants. `union`, `intersection`, `sum`, and `difference` are live read-only computations rather than eager copies, while `filter` is a live nullable-safe view whose permitted mutations write through. Direct Guava 33.6 traces cover these behaviors, including the live read-only contract of `Multisets.unmodifiableMultiset`, while JVM/JS/Wasm common tests exercise the portable mutation routes.

Sorted multisets now have a substantive KMP implementation: comparator-equivalent values share a count, range and descending results are live write-through views, polling removes complete boundary entries, and immutable/unmodifiable variants close their deep mutation routes. Immutable copies and builders support natural, reverse, and custom ordering with count operations. Direct Guava 33.6 traces lock down open/closed bounds, reverse-range mapping, reciprocal descending identity, zero-occurrence out-of-range calls, and comparison-versus-equality identity. Remaining sorted-collection work should broaden randomized differential sequences rather than reintroducing Java-only navigable collection types into common APIs.

BiMap now preserves its defining contract throughout the public shape: `HashBiMap` is a `BiMap`, `values` is a unique live set, inverse views are cached reciprocals and write through, `forcePut` evicts the conflicting mapping, and entry/key/value iterator mutations update both directions. Mutable maps distinguish nullable mappings from absence; immutable maps reject nulls and every tested deep mutation path with Guava-equivalent failures. Direct Guava 33.6 traces cover ordering, conflicts, inverse writes, view removals, entry replacement, inverse identity, and immutable failures on JVM, with the portable contract also running on JS and Wasm.

The core immutable migration shims now preserve the observable contracts that Kotlin read-only interfaces alone do not guarantee. `ImmutableList`, `ImmutableSet`, and `ImmutableMap` take snapshots, reject null elements/keys/values, preserve encounter order, and fail consistently through direct, iterator, entry, key, and value mutation routes. List reverse views are cached reciprocals, full sublists and safe immutable copies retain identity, and map builders distinguish strict duplicate rejection from `buildKeepingLast` while retaining first-key order. Direct Guava 33.6 tests cover these identities and failures on JVM, with the same portable contracts running on JS and Wasm. Kotlin stdlib collections remain the recommendation for ordinary new code.

Sorted immutable collections now use the same substantive comparator-backed core rather than shallow read-only delegation. `ImmutableSortedSet` and `ImmutableSortedMap` use comparator equivalence for membership, duplicate detection, and key lookup; support natural, reverse, and custom order; expose lower/floor/ceiling/higher navigation and inclusive/exclusive ranges; cache reciprocal descending views; reject nulls and all mutation routes; and retain safe immutable-copy and empty-range identities. Direct Guava 33.6 traces also preserve the non-obvious rule that `ImmutableSortedMap.Builder.buildKeepingLast` remains unsupported. The common API exposes navigation directly instead of pretending Java's `NavigableSet` and `NavigableMap` exist on every KMP target.

Immutable multimaps now have a substantive shared hierarchy instead of unrelated shallow wrappers. `ImmutableListMultimap` and `ImmutableSetMultimap` both inherit `ImmutableMultimap`, snapshot their complete nested structure, reject null keys and values, expose immutable key/value/entry/`asMap` views, and cache reciprocal inverse views. Builders may be reused without mutating earlier results; key comparators retain stable ties; list value comparators preserve duplicates; set value comparators use comparator equivalence for deduplication; copies preserve Guava's key-grouped order; and immutable keys multisets preserve first-occurrence order. Direct Guava 33.6 traces exercise those edge cases and mutation failures, while JVM/JS/Wasm tests cover the portable contract.

Immutable range collections now enforce their construction invariants rather than delegating to mutable range structures. `ImmutableRangeSet` distinguishes strict `copyOf`/builder overlap rejection from coalescing `unionOf`, orders and merges adjacent ranges by Guava cut semantics, implements `span`, descending ranges, clipped subranges, cached reciprocal complements, and immutable union/intersection/difference results. `ImmutableRangeMap` retains adjacent mappings, rejects empty or overlapping builder entries and null values, sorts by lower cuts, clips subrange maps, snapshots reusable builders, and returns deeply immutable ascending/descending maps. The pass also corrected unbounded `Range.encloses` and positive-infinity formatting. Direct Guava 33.6 traces and JVM/JS/Wasm contracts cover these rules.

`ContiguousSet` and `DiscreteDomain` now support `Int`, `Long`, unbounded common `BigInteger`, and valid custom domains instead of an `Int`-only materialized range. Creation resolves bounded domains for unbounded ranges, handles open endpoints, reports saturated sizes, and exposes constant-time `first`/`last`, factories, subset views, boundary-converting `range` overloads, and same-domain intersections. Standard numeric domains are singleton objects, long/arbitrary-integer distance matches Guava saturation, and `Range.canonical` normalizes discrete cuts. `ImmutableRangeSet.asSet(domain)` also now provides an immutable, lazy, saturating Kotlin `Set` view with Guava's bounded-domain validation; it does not expose JVM `NavigableSet` APIs in common code. Direct Guava 33.6 tests cover those boundaries, including property-controlled 180-digit RangeSet traces.

`TreeRangeSet` now keeps its complement and clipped subrange objects live, cached, and write-through, including nested complements. Its root ascending and descending `asRanges()` collections are also cached live views: removal, iterator removal, and clear update the backing set, while additions stay unsupported so coalescing remains centralized. Generated complement and subrange collections are likewise cached and live but use Kotlin's read-only `Set` surface, matching their unmodifiable Guava behavior without advertising mutation in common code; their held iterators fail fast after backing mutation. Direct Guava traces cover liveness, ordering, identity, write-through paths, iterator invalidation, comparator-equivalent cuts, and generated-view mutation failures.

`TreeRangeMap` now provides its Guava-shaped clipped subrange maps as live write-through views rather than detached copies. They enforce restricted insertion, clip removals and clear, preserve the special neighboring coalescing rule, clip entries and spans, compose nested views, and return an empty restricted map for disconnected nesting. Root and derived map-of-ranges views remain live, with removal, iterator-removal, and clear write-through; held iterators detect structural backing-map mutation like Guava. Only concrete mutable roots advertise Kotlin `MutableMap`, while the shared `RangeMap` interface remains read-only so immutable maps retain an honest type. Direct Guava traces cover held-view liveness, clipping, ordering, map-view identity, mutation routes, empty nested views, iterator invalidation, and failure behavior.

`ImmutableMultiset` now has its own substantive immutable contract rather than a shallow wrapper around a mutable snapshot. Construction preserves first-occurrence order, rejects null even on zero-copy builder calls, copies a source multiset by entries instead of expanding every occurrence, retains safe immutable-copy identity, and supports all public Guava-shaped factory and builder forms that make sense in common Kotlin. Reusable builders snapshot exact counts, `asList` is cached, element and entry views are immutable values, and direct, bulk, iterator, conditional-count, and nested-view mutations fail unconditionally. Direct Guava 33.6 traces cover values, failures, ordering, identity, and count validation; the same contract runs on JVM, JS, and Wasm.

The public `ImmutableClassToInstanceMap` contract is now substantive and Kotlin-shaped around `KClass`. Singleton and empty factories, safe immutable-copy identity, insertion order, typed lookup, reusable builder snapshots, `putAll`, strict duplicate-class rejection, and deeply immutable map/key/value/entry views are covered. Forged maps are runtime checked; direct Guava 33.6 tests also preserve the subtle builder rule that entries staged before a later invalid `putAll` mapping remain available. `ClassToInstanceMap` exposes typed mutation so mutable and immutable implementations share the meaningful Guava shape, while the immutable implementation rejects it unconditionally. Guava package-private helpers such as `ImmutableEnumMap`, `ImmutableAsList`, and `ImmutableMapEntrySet` are not counted as public parity milestones even where early GuavaKt compatibility shims remain.

BloomFilter now uses Guava's default Murmur128-MITZ-64 strategy rather than an approximate two-hash substitute. Integer, long, and unencoded-character funnels produce the same bit words and wire bytes as Guava 33.6, and either implementation can read the other's byte stream. The common implementation uses atomic words so concurrent writes and unions do not lose bits; copy/equality, compatibility rejection, expected FPP, approximate cardinality, validation, both Guava wire strategy ordinals, and stable standard-funnel equality are covered. The differential pass also found and corrected a wrong signed Murmur3-128 mixing constant, now pinned by direct short, block-boundary, long, and integer vectors. Okio `HashingSource`/`HashingSink` now bring stream hashing to common code without JVM stream types, including payload, close, failure, and Guava-vector coverage. Remaining hash work is custom-funnel breadth, Native execution, and measured performance rather than Bloom-filter format uncertainty.

The source half of common I/O now matches the Okio-native sink architecture. `ByteSource` primary operations open `okio.Source`; injected `FileSystem` sources no longer read the whole file before the caller consumes a byte. Slices skip and cap lazily without overflow, concatenation opens components only when reached, unknown-size emptiness probes stop after the first byte, direct copies leave caller-owned sinks open, and known sizes avoid opening the source. The early `ByteArrayInputLike` subclass hook remains supported through a streaming adapter, while `fromSource` is the Kotlin-first construction path. JVM oracle tests cover Guava slice, nested-slice, concat, aliasing, size, empty, and failure behavior; JVM/JS/Wasm contracts cover resource lifetime and incremental reads. `CharSource` and legacy platform string paths are the next buffering targets.

Table now has a shared `StandardTable` core with exact mutation bookkeeping and live row, column, cell, key, values, row-map, and column-map views. `Tables.transpose` is live and reversible, `transformValues` is lazy and removal-capable, `newCustomTable` honors its supplied backing structures, and `unmodifiableTable` remains live while rejecting mutation through nested collections and entries. `ArrayTable` models every fixed-grid cell including null slots, `TreeBasedTable` preserves global row/column comparator order, and `ImmutableTable` rejects nulls, duplicate coordinates, and deep mutation while supporting builder ordering. Direct JVM tests execute the same mutation, ordering, null, and failure traces against Guava; common tests cover Kotlin-facing behavior on the portable implementation.

Cache now has a separate coroutine-native path rather than disguising blocking `CacheLoader` as portable async work. Its synchronous compatibility layer also provides Guava-shaped `CacheLoader.loadAll`: ordered distinct miss batches, default single-key fallback, extra-result caching, incomplete-result validation after valid entries are retained, stable requested-key ordering, and aggregate load statistics are direct-compared. `buildCoroutine(scope)` shares one load per key while allowing other keys to proceed concurrently, keeps shared work alive when an individual waiter is cancelled, cancels it with the owner scope, retries failures, provides stale-while-revalidate for `Duration` refresh policies, and prevents invalidation or explicit writes from being overwritten by late loads. Common virtual-time tests cover these policies and separate coroutine work statistics from the backing Guava-shaped cache statistics.

Rate limiting now follows the same boundary. `CoroutineRateLimiter` uses cancellable delay, `Duration`, burst or cold-start warm-up, atomic timeout reservations, dynamic rates, and observable completed/cancelled/rejected counts. A cancelled waiter retains its committed reservation so cancellation cannot punch a hole in the throughput ceiling. The Guava-shaped `RateLimiter` now uses the same tested smooth-rate engine, no longer consumes permits on failed `tryAcquire`, restores JVM interrupt status after uninterruptible waits, and is explicitly documented as non-blocking-only outside JVM. Deterministic JVM oracle traces compare burst, warm-up, rate-change, validation, and formatting behavior directly with Guava 33.6.0.

Future and service migration now have a common coroutine boundary as well. `ListenableFuture.await`, `asDeferred`, `Deferred.asListenableFuture`, and `CoroutineScope.future` mirror the established kotlinx-coroutines Guava cancellation model without importing a JVM Guava type. `Service.awaitRunningSuspend`, `awaitTerminatedSuspend`, and `stateChanges` avoid blocking and make lifecycle ownership explicit. GuavaKt's service core now also matches Guava's deferred-stop-during-startup state machine, listener ordering, failure rules, and `setFuture` cancellation interrupt propagation through direct JVM oracle traces. JVM blocking methods remain migration-only; JS/Wasm/Native callers receive honest failures rather than fake blocking.

`ServiceManager` now adds consistent point-in-time snapshots, ordered aggregate `Flow`, real sorted startup durations, input-order stopping, correct empty-manager events, suspending healthy/stopped waits, and direct Guava lifecycle/failure/timeout traces. It intentionally enforces Guava's documented duplicate-service prohibition because Guava 33.6.0 still accidentally accepts duplicates into a manager whose set-backed state count can never reach its list-backed service count. `Monitor` now covers guarded entry, one-shot guarded entry, wait operations, `Duration` timeouts, fairness and ownership introspection, waiter accounting, reentrancy, and JVM interruption/restoration behavior. `CoroutineMonitor` is the portable primary API: `Mutex`-backed guarded blocks wake on state revisions without polling, do not time protected work after acquisition, and release safely on cancellation.

The JVM oracle is pinned to Guava 33.6.0. Its latest API delta is now executable evidence rather than inventory: `IntMath`/`LongMath.saturatedAbs`, Bloom-filter serialized sizing, eager `Striped.custom` and deadlock-safe `bulkGet`, endpoint-pair presentation and iteration, both transitive-closure self-loop strategies, `Graphs` copy/induced-subgraph/transpose behavior across `Graph`, `ValueGraph`, and `Network`, portable sorted/insertion element ordering, and live `Graph`/`ValueGraph.asNetwork` views are compared directly. Focused and seeded state traces now compare directed and undirected `ValueGraph` mutations plus parallel and non-parallel `Network` mutations after every operation, including relation views and invalid-node failures. Direct undirected sorted-node alias traces also preserve Guava's subtle two-level identity: the outer node map uses comparator equivalence while per-node adjacency retains raw keys. The view tests retain a returned edge set across mutation and node removal, which locks down both liveness and Guava's invalidation failure. Guava 33.6's stricter JSpecify bounds are preserved in the parity suite; deliberately-invalid runtime null probes cross a small Java oracle instead of weakening Kotlin production types.

## Definition of done for a capability

A capability is complete only when:

1. Its Kotlin API and intended divergences are documented.
2. Common behavior is implemented in `commonMain`; platform code is limited to genuine platform facilities.
3. Guava-equivalent behavior has direct typed differential tests, including failures and mutation through views.
4. Kotlin-specific behavior has tests for nullability, suspension, cancellation, structured ownership, and `Duration` where relevant.
5. JVM, JS, Wasm, and supported Native targets compile; behavior suites run on compatible CI hosts.
6. API baselines, Dokka, immutable/hollow/depth gates, and publication smoke tests pass.
7. Performance-sensitive features have reproducible benchmarks and no known pathological algorithmic regression.

## Feedback loop

Once public issue tracking exists, roadmap priority is determined in this order:

1. correctness or data-loss bugs;
2. migration blockers reported by real applications;
3. repeatedly requested differentiated capabilities;
4. platform parity gaps;
5. obscure Guava parity and low-use compatibility shims.

The long-term objective remains exhaustive sensible coverage. Demand changes the order, not the quality bar.
