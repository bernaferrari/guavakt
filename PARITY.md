# GuavaKt compatibility scope

GuavaKt ports useful Guava-shaped concepts to Kotlin Multiplatform. It does **not** promise source or binary compatibility with Guava and should not be advertised as a complete Guava rewrite.

## Compatibility levels

- **Differential:** representative outputs and failures are compared directly with a current Guava JVM dependency.
- **Contract-tested:** behavior is tested from the Guava contract, but the test does not execute Guava as an oracle.
- **Kotlin-shaped:** the concept is retained while signatures or idioms intentionally follow Kotlin.
- **Platform-limited:** the API depends on runtime facilities that do not exist consistently across targets.

## Latest depth updates

The earlier portable-`Long` math limitation is superseded: `dev.guavakt.math.BigInteger` and `BigDecimal` are common immutable arbitrary-precision values, not `java.math` wrappers. `BigInteger` now has JDK-shaped arithmetic, radix and signed-byte conversion, two's-complement bit operations, modular arithmetic, roots, and probable-prime utilities; `BigIntegerMath` uses it for Guava-shaped square roots, rounded division, factorial, binomial, and logarithms. `BigDecimal` has scale-preserving arithmetic, exact and rounded division, `MathContext`, precision rounding, point operations, engineering/plain rendering, square roots, and exact `Double` construction; `BigDecimalMath` accepts it and is direct-compared to Guava on hundred-digit, underflow, and overflow rounding cases. Direct JDK parity tests cover the portable value operations. These types intentionally do not claim Java serialization, `java.math` constructors, or JVM allocation/performance parity.

`DiscreteDomain.bigIntegers()` is an unbounded common domain with Guava-compatible saturating `Long` distance. The direct JVM parity suite runs 180-digit arithmetic and arbitrary-precision `TreeRangeSet` traces by default; [FUZZING.md](./FUZZING.md) controls prolonged replay counts. Graph/hash/cache JMH traces are documented in [BENCHMARKS.md](./BENCHMARKS.md). The checked-in PSL remains an offline snapshot; [PUBLIC_SUFFIX.md](./PUBLIC_SUFFIX.md) describes the semantic audit and reviewed compact-trie regeneration process.

## Permanent or deliberate differences

1. Public packages are `dev.guavakt.*`; `com.google.common.*` is reserved for Guava and never emitted by GuavaKt.
2. Kotlin stdlib replaces most List/Set/Map/Optional-style convenience APIs in new code.
3. Coroutines are the preferred asynchronous abstraction. Futures-shaped APIs exist for migration and specific composition use cases.
4. Java serialization layout, private implementation classes, exact heap layout, and binary linkage to Guava are out of scope.
5. Weak/soft references, real blocking, filesystems, ClassLoader scanning, and proxies are documented per target rather than emulated dishonestly. JVM finalizable references dispatch from a daemon GC-reference queue; other targets require explicit finalization.

## Evidence policy

Parity claims require typed tests that execute both Guava and GuavaKt and compare values, mutations, or exception behavior. Merely loading a Guava class, counting a file stem, or swallowing an oracle failure does not count as parity evidence.

The required local verification is:

```bash
./gradlew jvmTest :guavakt-parity:test --no-daemon
python3 scripts/hollow_inventory.py
python3 scripts/depth_inventory.py
python3 scripts/count_tests.py
python3 scripts/immutable_audit.py
```

The project is ready for an initial alpha only when these gates, cross-platform CI, API checks, Dokka generation, and publication validation are green.
